# 日本語文書と原文保持の方針

[フォルダー構成](FOLDER_LAYOUT.md)と、repository rootの日本語化済み運用文書を参照してください。文書内の英語の機能名・field名・状態値・コマンド・URLは、機械や画面と対応する識別子として保持しています。

| 区分 | 対応 |
|---|---|
| Git追跡の利用者・運用者向け説明 | 開発ブランチで意味を保って日本語化し、PRでreviewする。mainへ直接マージ／pullしない |
| 過去のaudit／packet／配備済みrelease内の説明 | hash固定の原文を保持し、別のdocs領域に日本語対訳または日本語解説とpath／SHA対応表を置く。逐語訳と要点解説を区別する。保護領域の実bytesが未読ならその制約を記録する |
| `tests/agent-repo/AGENTS.md` | 実エージェント指示を検証するfixtureのため原文を保持する。説明文書の翻訳とは分ける |
| `SecondBrain/AGENTS.md`と私有知識 | 実命令／私有データ。通常の製品説明Markdownの一括変換対象にしない |
| fixtureの原資料・モデル評価出力・機械protocol | 実際の入力bytesや契約識別子を保持し、日本語説明を分離する |
| 私有の`.original`・匿名化前の監査資料 | 公開・一般ログ・外部AIへ本文を出さず保全し、未確認範囲を明示する |
| Python／CUDA等の依存と第三者ライセンス | 原文を改変せず、必要な運用説明だけ日本語で添える |

翻訳の検査ではcode fence全体、inline code、URL、既存の見出しanchorを照合します。過去の試験件数や「公開fixture」と「実本番試験」の区別、通常停止／強制停止の違い、取消／冪等性／秘密保持の条件を変えません。日本語化だけで製品をbuild・配備・再起動する必要はありません。
